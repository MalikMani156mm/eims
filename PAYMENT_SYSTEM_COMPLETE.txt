### 3. Payment Processing
**Backend Logic** (`recordDOPayment.php` / `recordLedgerPayment.php`):
```php
// 1. Get current sale details
$sale = fetch from database

// 2. Validate payment amount
if ($paymentAmount > $pendingAmount) {
    throw error
}

// 3. Insert payment record
INSERT INTO do_sale_payments / ledger_sale_payments
- paymentDate (current datetime)
- amount (entered amount)
- paymentMethod ('Cash')
- notes (remarks)
- createdBy (current user ID)

// 4. Calculate new balances
$newPendingAmount = $oldPending - $paymentAmount
$newAmountPaid = $grandTotal - $newPendingAmount

// 5. Determine new status
if ($newPendingAmount <= 0) → 'paid'
elseif ($newAmountPaid > 0) → 'partial'
else → 'pending'

// 6. Update sale record
UPDATE do_sales / ledger_sales
SET amountPaid = $newAmountPaid,
    pendingAmount = $newPendingAmount,
    paymentStatus = $newStatus
```

### 5. Auto Status Updates
**Status Flow**:
```
PENDING (no payments yet)

PARTIAL (some paid, some pending)

```

**Status Badge Colors**:

## 💻 Usage Instructions

### How to Record a Payment

1. **Navigate to History Page**
   - DO: Menu → "DO Dispatch History"
   - Ledger: Menu → "Ledgers Dispatch History"

2. **Find the Dispatch**
   - Use search to filter
   - Look for dispatches with pending amount > 0

3. **Click Pay Button**
   - Purple "💰 Pay" button appears
   - Only visible if pending amount exists

4. **Enter Payment Details**
   - See pending amount in red box
   - Enter payment amount (e.g., 5000.00)
   - Add optional remarks (e.g., "Cash payment received")
   - Click "💰 Record Payment"

5. **Verify Update**
   - Page reloads automatically
   - Pending amount updated
   - Status badge changes if fully paid
   - Payment appears in history

### How to View Payment History

1. **Click View Button**
   - "👁️ View" on any dispatch

2. **Scroll to Payment History**
   - Below the payment summary section
   - Shows table with all payments

3. **Review Details**
   - Date/time of each payment
   - Amount paid
   - Remarks if any
   - Who recorded it

## 📊 Database Structure

### Payment Tables

**do_sale_payments**:
```sql
CREATE TABLE `do_sale_payments` (
  `paymentID` INT(11) PRIMARY KEY AUTO_INCREMENT,
  `saleID` INT(11) NOT NULL,
  `paymentDate` DATETIME NOT NULL,
  `amount` DECIMAL(10,2) NOT NULL,
  `paymentMethod` VARCHAR(50),
  `notes` TEXT,
  `createdBy` INT(11),
  `createdAt` TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (saleID) REFERENCES do_sales(saleID)
);
```

**ledger_sale_payments**:
```sql
CREATE TABLE `ledger_sale_payments` (
  `paymentID` INT(11) PRIMARY KEY AUTO_INCREMENT,
  `saleID` INT(11) NOT NULL,
  `paymentDate` DATETIME NOT NULL,
  `amount` DECIMAL(10,2) NOT NULL,
  `paymentMethod` VARCHAR(50),
  `notes` TEXT,
  `createdBy` INT(11),
  `createdAt` TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (saleID) REFERENCES ledger_sales(saleID)
);
```

## 🛡️ Security Features

1. **Authentication Required**
   - Uses `adminAuth.php` (JWT validation)
   - Only authenticated users can record payments

2. **Input Validation**
   - Frontend: HTML5 validation (required, min, max)
   - Backend: Type checking and range validation

3. **Transaction Safety**
   - Uses `$conn->begin_transaction()`
   - Rollback on any error
   - Prevents partial updates

4. **SQL Injection Prevention**
   - Prepared statements with `bind_param()`
   - All inputs sanitized

5. **Amount Validation**
   - Cannot exceed pending amount
   - Must be positive number
   - Decimal precision (2 places)

## 🔧 Troubleshooting

### Issue: Pay button not showing
**Solution**: Check if `pendingAmount > 0` in database

### Issue: Payment not saving
**Solution**: 
1. Check browser console for errors
2. Verify payment tables exist in database
3. Check user has valid `user_id` in session

### Issue: Status not updating
**Solution**: 
1. Check status ENUM values match ('paid','partial','pending')
2. Verify calculation logic in backend

### Issue: Payment history not showing
**Solution**:
1. Check `getDispatchDetails.php` includes payments query
2. Verify `users` table has `full_name` column
3. Check foreign key `createdBy` matches `user_id`

### Issue: Modal not closing
**Solution**: 
1. Check JavaScript errors in console
2. Verify modal IDs are unique
3. Test close button onclick event
