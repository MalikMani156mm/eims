Created three tables identical to DO system but for ledgers:
- `ledger_sales` - Main sales table with ledger name (runtime entry, not pre-registered)

## 🎯 How The System Works

### Ledger Entry Flow

1. **First Time Ledger**:
   - User types "ABC Traders" in dropdown
   - "(New Ledger)" tag appears
   - User enters CNIC, contact, address manually
   - Creates sale → Ledger saved in `ledger_sales`

2. **Existing Ledger**:
   - User selects "ABC Traders (Pending: Rs. 5000)" from dropdown
   - System auto-fills CNIC, contact, address from last sale
   - User can edit details if needed
   - Creates sale → New record with updated details

3. **Ledger Lookup Logic**:
```sql
SELECT 
    ledgerName,
    ledgerCNIC,  -- From most recent sale
    ledgerContact,
    ledgerAddress,
    SUM(pendingAmount) as pending
FROM ledger_sales
GROUP BY ledgerName
ORDER BY MAX(saleID) DESC  -- Most recent first
```

### Due Date Calculation

**Same as DO System**:
```javascript
// Frontend calculates display date
const saleDate = $('#saleDate').val();  // "2026-03-15"
const days = parseInt($('#paymentDays').val());  // 30

const date = new Date(saleDate);
date.setDate(date.getDate() + days);  // March 15 + 30 = April 14

// Backend calculates actual stored date
$saleDateObj = new DateTime($saleDate);
$saleDateObj->modify('+30 days');
$dueDate = $saleDateObj->format('Y-m-d');  // "2026-04-14"
```

## 🔄 Comparison: DO vs Ledger Systems

| Feature | DO System | Ledger System |
|---------|-----------|---------------|
| **Selection** | Dropdown from `distributing_officer` table | Select2 with tags (runtime entry) |
| **Pre-Registration** | Yes, must add DO first | No, type on-the-fly |
| **Data Storage** | DO details in `distributing_officer` | Ledger details in `ledger_sales` |
| **Details Update** | Edit DO record separately | Stored per sale |
| **Pending Tracking** | Aggregated per DO | Aggregated per ledger name |
| **Color Scheme** | Purple gradient | Green gradient |
| **Receipt** | generateDOReceipt.php | generateLedgerReceipt.php |

## 📊 Database Schema

### ledger_sales Table
```sql
saleID (PK)
ledgerName VARCHAR(255) -- Typed or selected
ledgerCNIC VARCHAR(20) -- Optional
ledgerContact VARCHAR(20) -- Optional
ledgerAddress TEXT -- Optional
saleDate DATETIME
totalAmount DECIMAL
discountAmount DECIMAL
grandTotal DECIMAL
amountPaid DECIMAL
pendingAmount DECIMAL
paymentDays INT(11) -- Max 45
dueDate DATE -- Calculated
paymentStatus ENUM('paid','partial','pending')
createdBy INT(11) -- user_id
createdAt, updatedAt TIMESTAMP
```

### ledger_sale_items Table
```sql
itemID (PK)
saleID (FK → ledger_sales)
serialID (FK → product_serials)
productID (FK → products)
batchNumber VARCHAR(100)
sellingPrice DECIMAL
discountPercent DECIMAL(5,2)
discountAmount DECIMAL
finalPrice DECIMAL
createdAt TIMESTAMP
```
