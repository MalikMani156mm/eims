## 🔄 Key Differences: DO vs Ledger

| Feature | DO System | Ledger System |
|---------|-----------|---------------|
| **Color** | Purple (#667eea) | Green (#11998e) |
| **Selection** | Dropdown from DB | Select2 with tags |
| **Pre-Registration** | Required | Not required |
| **Details Storage** | In distributing_officer table | In each ledger_sales record |
| **Data Join** | JOIN with distributing_officer | No JOIN needed |
| **Auto-Fill** | From DO table | From previous sales |
| **Columns** | DO_Name, CNIC, contactNumber, Address | ledgerName, ledgerCNIC, ledgerContact, ledgerAddress |

## 📊 Database Structure

### ledger_sales (Main Table)
```sql
saleID          INT(11) PRIMARY KEY AUTO_INCREMENT
ledgerName      VARCHAR(255) NOT NULL -- Runtime entry
ledgerCNIC      VARCHAR(20)          -- Optional
ledgerContact   VARCHAR(20)          -- Optional
ledgerAddress   TEXT                 -- Optional
saleDate        DATETIME
totalAmount     DECIMAL(10,2)
discountAmount  DECIMAL(10,2)
grandTotal      DECIMAL(10,2)
amountPaid      DECIMAL(10,2)
pendingAmount   DECIMAL(10,2)
paymentDays     INT(11)
dueDate         DATE                 -- Calculated
paymentStatus   ENUM('paid','partial','pending')
createdBy       INT(11)              -- user_id
createdAt       TIMESTAMP
updatedAt       TIMESTAMP
```

### ledger_sale_items
```sql
itemID          INT(11) PRIMARY KEY
saleID          INT(11) FK → ledger_sales
serialID        INT(11) FK → product_serials
productID       INT(11) FK → products
batchNumber     VARCHAR(100)
sellingPrice    DECIMAL(10,2)
discountPercent DECIMAL(5,2)
discountAmount  DECIMAL(10,2)
finalPrice      DECIMAL(10,2)
createdAt       TIMESTAMP
```

### ledger_sale_payments
```sql
paymentID       INT(11) PRIMARY KEY
saleID          INT(11) FK → ledger_sales
paymentDate     DATETIME
amount          DECIMAL(10,2)
paymentMethod   VARCHAR(50)
notes           TEXT
createdBy       INT(11)
createdAt       TIMESTAMP
```

## 🔧 Troubleshooting

### Issue: Ledger dropdown not working
**Solution**: Check Select2 is initialized with `tags: true`

### Issue: Details not auto-filling
**Solution**: Verify `getLedgers.php` returns correct data and check console for errors

### Issue: Due date wrong
**Solution**: Check sale date is set before calculating payment days, use DateTime objects

### Issue: Overdue badge not showing
**Solution**: 
1. Check `getLedgerOverdueCount.php` returns correct count
2. Verify `updateOverdueCount()` function calls ledger API
3. Check badge ID is `overdueCountLedger` not `overdueCount`

### Issue: Receipt not generating
**Solution**: Check `generateLedgerReceipt.php` has correct column names (ledgerName, ledgerCNIC, etc.)

### Issue: View modal shows wrong data
**Solution**: Verify API call uses `backend/getLedgerDispatchDetails.php` not `getDispatchDetails.php`

## 🎯 Quick Reference Commands

### View All Ledger Sales
```sql
SELECT * FROM ledger_sales ORDER BY saleDate DESC;
```

### View Pending Ledgers
```sql
SELECT ledgerName, SUM(pendingAmount) as total_pending
FROM ledger_sales
WHERE paymentStatus IN ('pending', 'partial')
GROUP BY ledgerName
ORDER BY total_pending DESC;
```

### View Overdue Ledgers
```sql
SELECT * FROM ledger_sales
WHERE paymentStatus IN ('pending', 'partial')
  AND dueDate IS NOT NULL
  AND dueDate != '0000-00-00'
  AND dueDate < CURDATE()
ORDER BY dueDate ASC;
```

### View Today's Dispatches
```sql
SELECT * FROM ledger_sales
WHERE DATE(saleDate) = CURDATE()
ORDER BY createdAt DESC;
```
