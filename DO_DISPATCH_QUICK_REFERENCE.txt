# DO Dispatch System - Quick Reference

## What Was Created

### 1. Database Tables (do_sales_tables.sql)
```
do_sales              - Main sales/dispatch records
do_sale_items         - Individual products sold  
do_sale_payments      - Payment history tracking
```

### 2. Frontend Interface
**File**: `content/dispatchToDO.php`

**Features**:
- ✅ DO Selection Dropdown (Select2)
- ✅ Serial Number Scan/Entry
- ✅ Barcode Scanner Compatible
- ✅ Real-time Product Lookup
- ✅ Editable Selling Prices
- ✅ Percentage Discount
- ✅ Auto-calculated Totals
- ✅ Payment Terms (Max 45 days)
- ✅ Due Date Calculator
- ✅ Beautiful Gradient UI

### 3. Backend APIs

**get ProductBySerial.php**
- Input: serialNumber
- Output: Product details with batch cost
- Validates: Availability status

**saveDispatchToDO.php**
- Input: JSON (DO_ID, items, payment details)
- Creates: Sale record + items + payments
- Updates: Serial status, available quantity
- Uses: Database transactions

**generateDOReceipt.php**
- Input: saleID
- Output: Printable HTML receipt
- Shows: DO details, products, pricing, payments

## Key Fields

### DO Sales Table
- `saleID` - Auto-increment primary key
- `DO_ID` - Foreign key to distributing_officer
- `grandTotal` - Final amount after discounts
- `amountPaid` - Amount paid upfront
- `pendingAmount` - Remaining balance
- `paymentDays` - Days to pay (max 45)
- `dueDate` - Calculated due date
- `paymentStatus` - paid/partial/pending

### DO Sale Items Table
- `saleID` - Links to do_sales
- `serialID` - Links to product_serials
- `sellingPrice` - Price per item
- `discountPercent` - Discount percentage
- `finalPrice` - After discount price

## Important Notes

✅ **Serial Number Validation**
- Must exist in product_serials
- Must have status 'available'
- Cannot be dispatched twice

✅ **Inventory Updates**
- Serial status changes to 'sold'
- Available quantity decreases
- Changes are permanent

✅ **Payment Terms**
- Max 45 days allowed
- Due date auto-calculated
- Status: paid/partial/pending

✅ **Transaction Safety**
- All saves use database transactions
- Rollback on any error
- Data integrity guaranteed

## Calculations

**Discount Amount** = Selling Price × Discount % ÷ 100
**Final Price** = Selling Price - Discount Amount
**Grand Total** = Sum of all Final Prices
**Pending Amount** = Grand Total - Amount Paid
**Due Date** = Dispatch Date + Payment Days

## Default Behavior

- Selling Price = Batch Cost (editable)
- Discount = 0% (editable)
- Amount Paid = 0 (editable)
- Payment Days = 0 (editable, max 45)
- Dispatch Date = Today (editable)

**Before Dispatch**:
- Serial Status: 'available'
- Product Available: N
- DO Sale: None

**After Dispatch**:
- Serial Status: 'sold'
- Product Available: N-1
- DO Sale: Created with items

## Database Schema

```sql
do_sales
├── saleID (PK)
├── DO_ID (FK → distributing_officer)
├── saleDate
├── totalAmount
├── discountAmount
├── grandTotal
├── amountPaid
├── pendingAmount
├── paymentDays
├── dueDate
├── paymentStatus (enum)
├── createdBy (FK → users)
└── timestamps

do_sale_items
├── itemID (PK)
├── saleID (FK → do_sales, CASCADE)
├── serialID (FK → product_serials)
├── productID (FK → products)
├── batchNumber
├── sellingPrice
├── discountPercent
├── discountAmount
├── finalPrice
└── createdAt

do_sale_payments
├── paymentID (PK)
├── saleID (FK → do_sales, CASCADE)
├── paymentAmount
├── paymentDate
├── paymentMethod
├── notes
└── createdAt
```
