# DO Dispatch/Sales System Setup Instructions

## Overview
This system allows dispatching products to Distributing Officers (DO) with serial number scanning, pricing management, discount tracking, and payment terms management.

## Database Setup

1. Run the SQL file to create required tables:
   ```sql
   mysql -u root -p eims_db < do_sales_tables.sql
   ```
   
   Or manually execute the SQL from:
   `c:\xampp\htdocs\eims\do_sales_tables.sql`

   This creates three tables:
   - `do_sales` - Main sales/dispatch records
   - `do_sale_items` - Individual products sold
   - `do_sale_payments` - Payment history tracking

## Files Created

### Frontend
- `content/dispatchToDO.php` - Main dispatch interface
  * DO selection dropdown
  * Serial number scanning
  * Product table with pricing/discounts
  * Payment tracking
  * Grand total calculations

### Backend
- `backend/getProductBySerial.php` - Fetches product details by serial number
  * Validates serial number exists
  * Checks product availability status
  * Returns complete product information

- `backend/saveDispatchToDO.php` - Saves dispatch transaction
  * Creates sale record in do_sales
  * Inserts all items in do_sale_items
  * Updates product_serials status to 'sold'
  * Decrements available quantity in products table
  * Records initial payment if provided
  * Uses transaction for data integrity

- `backend/generateDOReceipt.php` - Generates printable receipt
  * Shows DO details
  * Lists all products with pricing
  * Displays payment summary
  * Shows payment terms and due date

## Workflow

1. **Select DO**: Choose from active distributing officers
2. **Scan Products**: Enter serial numbers (manually or via barcode scanner)
3. **Verify Products**: System shows product details with batch cost
4. **Adjust Pricing**: Edit selling price and discount if needed
5. **Enter Payment**: Specify amount paid and payment days
6. **Submit**: Creates dispatch record and updates inventory
7. **View Receipt**: Print or download receipt

## Database Impact

When a dispatch is saved:
1. Record created in `do_sales` table
2. Items added to `do_sale_items` table
3. Serial numbers marked as 'sold' in `product_serials`
4. Available quantity decremented in `products` table
5. Initial payment recorded in `do_sale_payments` (if provided)

## Validations

- DO selection required
- At least one product required
- Serial numbers must be unique within sale
- Products must have 'available' status
- Payment days cannot exceed 45
- All transactions use database transactions for integrity

## Notes

- Only products with status 'available' can be dispatched
- Serial numbers are unique - cannot be sold twice
- Discount is percentage-based (0-100%)
- Payment days max is 45 days
- Due date is calculated from dispatch date
- Receipt opens in new window/tab
- All currency amounts use decimal(10,2)
- System uses transactions to prevent partial saves

## Troubleshooting

**Serial number not found**
- Verify serial number exists in product_serials table
- Check spelling and format

**Product not available**
- Check product status in product_serials table
- May already be sold, reserved, or damaged

**Failed to create dispatch**
- Check browser console for errors
- Verify database tables exist
- Check foreign key constraints
- Ensure distributing officer status is active (0)

**Receipt not generating**
- Verify saleID is valid
- Check database for sale record
- Ensure all joins return data
